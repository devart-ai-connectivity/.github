# Security Policy

Security is a core consideration for repositories in the `devart-ai-connectivity` organization.

The current public repositories in this organization are focused on Devart MCP Servers, which are designed to help AI tools connect to databases and cloud applications in self-hosted and on-premises environments.

## Reporting a vulnerability

Please **do not** report security vulnerabilities through public GitHub issues, discussions, or pull requests.

Instead, report them privately using one of the approved private channels below:

- Security contact: <replace-with-security-email>
- Contact form: https://www.devart.com/company/contactform.html
- Trust Center: https://www.devart.com/data-connectivity/trust-center.html

## What to include

Please include as much of the following as possible:

- affected repository and product
- affected version
- operating system and environment
- AI tool used
- ODBC driver used
- steps to reproduce
- impact and severity
- proof of concept, if available
- logs, screenshots, or sample requests, if relevant

## Please do not include

Do not include secrets or live production credentials in your report, such as:

- passwords
- API keys
- access tokens
- private certificates
- full connection strings
- customer data
- production database contents

If needed, redact or sanitize any sensitive values before sending them.

## Scope

This policy applies to repositories in the `devart-ai-connectivity` organization unless a repository provides its own local `SECURITY.md`.

## Response process

We will review reported issues, validate them, assess severity, and respond through the private reporting channel.

Response times may vary depending on the nature and complexity of the report.

## Supported versions

Unless otherwise stated in a repository, security review is focused on currently maintained versions and active public releases.

## Responsible disclosure

Please give us a reasonable opportunity to investigate and address the issue before sharing details publicly.
