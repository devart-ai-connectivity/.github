# Contributing

Thanks for your interest in improving repositories in the `devart-ai-connectivity` organization.

At the moment, the public repositories in this organization are focused on **Devart MCP Servers**.

## What is most helpful right now

The most useful contributions at this stage are:

- bug reports
- documentation fixes
- setup and installation clarifications
- reproducible usage examples
- focused improvements to samples and repository content

## Before contributing

Please do the following first:

1. Read the repository README
2. Check the documentation
3. Search existing issues
4. Open an issue before proposing large changes

## Bug reports

When reporting a bug, please include:

- affected repository and product
- product version
- operating system
- AI tool used
- ODBC driver used
- steps to reproduce
- expected result
- actual result
- logs or screenshots, if available

Please do not include secrets, credentials, tokens, private connection strings, or customer data in public issues.

## Documentation improvements

Documentation feedback is very welcome, especially around:

- installation
- activation
- connection setup
- AI tool integration
- troubleshooting
- repository structure and examples

## Pull requests

Small, focused pull requests are preferred.

Examples of good pull requests:

- fix a typo or broken link
- improve a setup step
- clarify a README section
- improve a sample without changing overall product direction

For larger changes, please open an issue first so maintainers can confirm scope and direction.

## Contribution review

All contributions are reviewed by Devart maintainers.

Submitting an issue or pull request does not guarantee that it will be accepted, merged, or included in a release.

Acceptance depends on factors such as:

- product scope
- roadmap fit
- maintenance cost
- consistency with repository direction

## Repository-specific rules

Some repositories may include additional local contribution notes, build instructions, or review requirements.

If a repository contains its own `CONTRIBUTING.md`, follow the local file for that repository.

## Security issues

If your contribution or issue involves a possible security vulnerability, do not open a public issue.

Please use the private reporting process described in `SECURITY.md`.
